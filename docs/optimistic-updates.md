# 간트 변경의 공통 처리

`web/mutations.js`가 확정 데이터와 대기 중인 변경을 소유한다. `web/app.js`의 모든 POST / PUT / PATCH / DELETE는 `api()` → `chartMutations.mutate()`를 통과한다. 개별 이벤트에서 `state.data`를 수정하거나 서버 응답으로 덮어쓰지 않는다.

## 변경 범주

| 범주 | 즉시 화면에 반영하는 내용 | 서버 응답 처리 |
| --- | --- | --- |
| 작업 속성·진행률·완료 | 이름, 색, 그룹, 태그, 메모, 상태, 프로젝트 진행률 | 정규화된 작업 및 프로젝트를 확정 |
| 날짜·간트 드래그 | 예정/실제 시작·종료일, 전체 구간 이동 | 같은 작업 속성 경로 사용 |
| 선후행 관계·연동 날짜 | 연결선 및 도달 가능한 후행 작업의 예정 날짜 | 예정/실제 중 늦은 종료일 차이를 달력 일수로 적용; 합류 작업은 한 번만 이동 |
| 순서·소속 이동 | 행 순서, 이동한 작업, 프로젝트를 넘는 연결 제거 | 서버가 반환한 대상 프로젝트 확정; 출발 프로젝트도 로컬 reducer로 갱신 |
| 추가·템플릿 적용·복제 | 임시 ID로 프로젝트/작업 표시 | 실제 ID로 치환; 임시 항목에 대한 대기 중 편집 경로도 치환 |
| 삭제 | 행 및 관련 연결 제거 | 실패 시 확정 데이터에서 복원 |
| 템플릿 편집 | 기존 draft와 템플릿 간트가 즉시 갱신 | 최초 생성 ID를 받기 위한 draft 저장 큐는 유지하고 HTTP는 공통 처리기로 전달; draft/커서 유지 |
| 태그 색·공휴일 설정 | 색상·선택한 설정 값 | 공휴일 자료는 별도 조회; 기존 프로젝트의 저장 날짜는 재계산하지 않음 |
| 화면 전용 상태 | 선택, 펼침/접힘, 필터, 축척 | 서버 저장 없이 기존 로컬 상태 유지 |

템플릿 수정은 이미 생성된 프로젝트 작업을 변경하지 않는다. 프로젝트 시작일과 달력 메타데이터를 변경해도 기존 작업 날짜는 이동하지 않는다.

## 처리 순서와 실패 복구

1. 사용자 변경을 대기 목록에 추가하고 `확정 데이터 + 대기 변경 순서 적용` 결과를 동기적으로 발행한다.
2. 네트워크 저장은 공통 큐에서 순서대로 보낸다. 화면 갱신은 이 큐를 기다리지 않는다. 저장 중에도 다음 편집이나 날짜 드래그를 시작할 수 있다.
3. 성공 응답을 확정 데이터에 반영하고 해당 변경을 제거한 뒤, 더 최근의 대기 변경을 다시 적용한다. 오래된 응답이 최신 편집을 덮어쓰지 않는다.
4. 실패한 변경만 제거하고 같은 방식으로 화면을 다시 계산한다. 연속 실패가 이전의 실패 값을 되살리지 않는다. 기존 필드 오류 표시와 재시도 동작을 유지한다.
5. `/api/state` 조회 중 새 변경이 발생하면 해당 조회 결과를 버리고 다시 읽는다. 성공한 저장 뒤 별도 조회가 실패해도 저장된 변경을 되돌리지 않는다.

일반 저장 후 전체 `/api/state` 재조회는 하지 않는다. 저장 응답으로 공통 상태를 확정한다. 초기 로드·명시적 갱신·공휴일/시간대 변경 등 실제 조회가 필요한 곳에서만 읽는다.

속성 입력의 미저장 초안과 포커스는 유지한다. 입력 중이지 않은 깨끗한 필드는 공통 상태에 맞게 갱신한다. 드래그로 포인터를 잡고 있는 동안에는 바 DOM을 교체하지 않고 드래그 이후 다시 그린다.

## 서버가 최종 결정하는 값

생성 ID, 색상 선택, 이름/태그 정규화와 공휴일 자료는 서버가 최종 결정한다. 템플릿 생성 미리보기는 현재 로드된 공휴일로 계산하고 서버 응답의 날짜로 확정한다. 화면 범위 밖 공휴일이 포함되면 미리보기와 확정 날짜가 다를 수 있다. 서버가 요청을 처리한 뒤 응답만 유실된 경우 자동 재전송하지 않으며, 명시적 새로고침으로 서버 상태를 확인한다.

이 구조는 페이지 안의 변경 순서를 보장한다. 오프라인 영구 저장소나 여러 브라우저 간 버전 충돌 해결 기능은 포함하지 않는다.

## 검증

- `node --test tests/*.cjs`: 공통 처리기, 기존 입력·드래그·템플릿 회귀 테스트.
- `python3 -m unittest tests.test_mutation_contract`: 실제 SQLite 계산과 프론트 미리보기 비교.
- `test_mutations.cjs`: 응답 대기 중 즉시 반영, 연속 편집/실패, 관계 복구, 임시 ID 치환, 오래된 조회 무시, 저장 후 조회 실패.
- 격리 DB + PATCH 8초 지연 서버에서 브라우저의 ‘저장 중…’ 상태와 변경된 간트 표시를 확인. 사용자의 실제 일정 DB에는 테스트 변경을 기록하지 않음.
